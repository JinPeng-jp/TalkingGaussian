# 在线时延测量口径（2026-10-09）

## 总值不是估算，也不是物理声光时延

页面总值直接计算：

`浏览器 rAF 中 drawImage 返回时的 performance.now() - 来源音频块回调入口的 performance.now()`

两个端点来自**同一浏览器页面、同一单调时钟**。服务器原样回传浏览器时间戳，不用浏览器与服务器的系统时钟作差。没有把 480 ms、半块采样、半帧等待或 RTT/2 加进总值。

来源块的选择：训练 attention 上下文为 `[t-4, ..., t+3]`，当前窗口为索引 4。在线端为每个 16-logit 窗口保存其在已消费 PCM 流中的名义中心样本位置：

`已消费样本数 - 滚动窗样本数 + (窗口起始 logit 索引 + 8) × 采样率 / 50`

这里是现有特征提取代码的 20 ms 索引网格，不是自动识别出的音素/口型事件。寻找包含该样本位置的实际输入包，回传其回调时间，而不是选择最近到达的包。这样可以覆盖目标块到达后继续等待上下文的时间。计算出的样本地址只用于追溯来源，不作为理论时间加项。

测量粒度是 **ScriptProcessor 音频块回调**，不是块中某个采样点被麦克风 ADC 获取的时间。4096 个输入采样构成一个回调，因此不能将该值直接当作采样级、音素级时延。回调前采样/操作系统缓冲、屏幕扫描、扬声器输出，以及实际音画同步误差均不在测量边界内。`drawImage` 返回只表示 Canvas 提交，不保证像素已经物理呈现。

## 同一帧分项

| 分项 | 端点与含义 |
| --- | --- |
| 浏览器回调内处理 | 回调入口 → PCM 已准备好、开始构建发送元数据 |
| 音频到达 → 本轮 ASR 开始 | 来源块 WebSocket 处理入口 → 生成该帧所需的最后一轮 ASR 开始；包含上下文等待、重分块、进程队列和此前计算，不是纯上下文理论值 |
| 最后一轮 ASR | MFCC 构建及 TensorFlow `session.run`，直到 logits 返回；历史窗口此前的计算已处于上一项区间中 |
| ASR 完成 → 渲染开始 | 特征包装、进程传递、特征队列、帧调度；不是半帧理论值 |
| 渲染及编码 | 同一次 `render_jpeg` 调用；图像 `.cpu().numpy()` 等待 GPU 数据后再编码 JPEG |
| 渲染完成 → 发包准备 | 发布、视频额度等待及事件循环调度，直到组装当前发包元数据 |
| 浏览器收包 → Canvas 提交 | 包解析、解码、rAF 等待及绘制提交；HTTP 备用路径从完整响应体读完开始 |
| 往返传输与调度 | `浏览器收包 - 浏览器发送标记 - (服务器发包准备 - 来源块接收)`；差额包含包序列化、两向网络、WebSocket/HTTP 缓冲和回调调度，**不是单向网络时延** |

以上八项与总值使用同一条 trace，未四舍五入前可以相加复核。服务器区间全部用 `time.monotonic()`，Linux 同机不同进程共享其时间基准。浏览器和服务器的时钟偏移不参与计算；极小的时钟频率漂移、浏览器计时器精度仍是软件测量的限制。逆序/非有限/负差额的时间戳不展示为有效测量。

状态接口请求往返（最近 12 次中位数）独立显示，**不再除以 2，也不计入总值**。首个驱动画面的等待独立计算（本轮第一个发送回调到首个 traced Canvas 提交），包括预热；它不是检测到首个嘴部动作的时刻。

## 统计、导出与播放

- 只有发起音频的同一页面能计算总值。其他观看页面显示 `--`，不借助时钟校准伪造单向/跨客户端测量。
- 模型切换、重新开始输入时清空会话；停止后实时值清空，保留本轮统计供导出。
- 每个特征只统计第一次可见 Canvas 提交，避免重复渲染同一特征产生虚高延迟。丢弃帧、隐藏页帧不纳入样本；这不是全部已生成帧的延迟分布。
- 统计为最近 300 个有效样本的中位数/P95/最大值，JSON 保存最近 10000 个逐帧样本及原始时间戳、会话、音频块/特征编号。不能将分项分别取中位数后相加当作总值。
- 音频播放延后是**控制设置**，不是测量值或同步精度。保持播放期间锁定，防止 DelayNode 频繁改变引起尖锐变调；自动模式仅在下一轮使用上一轮链路中位数，首次保留 570 ms 初始设置。该设置仍可手动校正。
- 原有时钟校准仅供内部视频拥塞控制使用，不用于任何展示的实测时延。下方原“画面帧龄”已改为本机距最近 Canvas 提交时间。

## 协议与兼容

- 新音频连接 `/ws/audio?trace=1`：`TGA1` + 网络字节序 uint32 JSON 长度 + JSON + little-endian int16 PCM；不带参数的旧客户端仍发送裸 PCM。
- 新视频连接 `/ws/video?trace=1`：原 12 字节（uint32 序号、float64 Unix 生成时间）+ uint32 JSON 长度 + trace JSON + JPEG；旧视频连接保持原格式。
- HTTP `/frame.jpg` 同一锁下获取图像和 trace，经 `X-Frame-Trace` 返回；同样不使用跨时钟相减。
- 中立/无来源的帧返回空 trace，不填造来源时间。

```sh
python -m unittest scripts.test_latency_trace -v
node scripts/test_latency_metrics.js
# 服务空闲时执行：会依次播放两个验证音频和浏览器虚拟麦克风。
```
